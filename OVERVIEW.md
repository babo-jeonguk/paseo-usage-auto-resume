Usage Auto Resume continues the same Codex, Claude, or Antigravity agent after a provider usage limit resets. It handles session and weekly limits when the provider notice or account usage information supplies the reset time, and schedules a continue prompt two minutes after that time.

The Auto Resume sidebar screen lists pending resumes by day, with the send time, countdown, agent title, provider and workspace. Open a row to return to the conversation. Each reservation starts enabled; its switch takes effect immediately and can be turned back on before the scheduled time.

Requires Paseo daemon and app 0.11.x, with plugins enabled. The default provider IDs are `codex`, `claude`, and `antigravity`. In the plugin settings, choose the exact Claude, Codex, and Antigravity IDs to resume and save the selection. For example, setting the Claude ID to `claude-main` replaces `claude` and does not include `claude-sub`. A custom ID must use the corresponding CLI, normally by extending its built-in provider. The selection is stored per daemon; saving cancels pending reservations for removed providers. The plugin uses the accounts already signed in through their CLIs.

To match account usage, the daemon reads the account email from Claude's `.claude.json` or the email claims in Codex's `auth.json`, using the configured `CLAUDE_CONFIG_DIR` or `CODEX_HOME`. Paseo has no Antigravity usage information, so Antigravity resumes rely on the reset time stated in the notice, else the 15-minute recheck. It reads agent state, recent timeline notices and Paseo usage information, stores resume jobs under `PASEO_HOME/plugin-data/usage-auto-resume/jobs.json`, and sends a fixed continue prompt to the existing agent through Paseo. The prompt asks the parent to continue unfinished work and any unfinished subagents stopped by the limit. Login tokens are not included in saved jobs, logs or the continue prompt.

A new turn, a newer user message, an archived or closed agent, or an agent running or awaiting permission cancels the resume. Just before sending, Claude and Codex resumes recheck the account's usage and are postponed to the reset of any window that is still exhausted; if usage cannot be read, or for Antigravity, the continue is sent as scheduled. Unreadable provider settings pause automatic resumes instead of enabling defaults. Reservations survive restarts, but need a lifecycle event or the Auto Resume screen to supply the API before they can run again. If the reset time remains unknown, the plugin rechecks after 15 minutes and may retry the continue prompt, stopping after 24 consecutive unsuccessful automatic continues. Context overflow and billing failures are excluded. Subagent continuation depends on the parent's available provider tools.
