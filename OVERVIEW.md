Usage Auto Resume continues the same Codex, Claude, or Antigravity agent after a provider usage limit resets. It handles session and weekly limits when the provider notice or account usage information supplies the reset time, and schedules a continue prompt two minutes after that time.

The Auto Resume sidebar screen lists pending resumes by day, with the send time, countdown, agent title, provider and workspace. Each reservation starts enabled; its switch takes effect immediately and can be turned back on before the scheduled time. A row can be pushed back 10 minutes, moved to a typed time (never before the limit resets), or opened in its conversation with its open button, and one header button turns every reservation off or back on.

Requires Paseo daemon and app 0.11.0 or later, with plugins enabled. Every provider that runs Claude, Codex, or Antigravity is considered for verified subscription resumes: the built-in `claude`, `codex`, and `antigravity`, and providers that extend them, such as `claude-main` or `codex-sub`. The plugin settings list these providers by CLI, with the account each signs in as, and give each one a switch that takes effect immediately. Turning a provider off cancels its pending reservations, and turning it back on does not restore them. The switches are stored per daemon. The plugin uses the accounts already signed in through their CLIs.

The plugin captures non-secret launch context at session open and verifies actual CLI authentication before using subscription quotas. API and external billing routes are excluded. Codex account/config status and exact workspace/model usage, or Claude auth status plus OAuth profile/usage, provide account-bound checks. OAuth tokens are used only for read-only requests and are never refreshed, persisted in jobs or logged. Jobs retain hashed account/model identity and sanitized launch paths/credential-presence flags. Sessions opened before the plugin loaded are checked with the daemon and provider environment instead. Antigravity versions without reliable account identity and unsupported metadata wait for verification.

A new turn, a newer user message, an archived or closed agent, or an agent running or awaiting permission cancels the resume. Before sending, fresh subscription state must confirm recovery. Unknown authentication, unreadable usage, and stale exhausted windows wait for a read-only recheck. The 5-hour and weekly windows decide every stop, including credit and spending notices: a used-up window waits for its reset, otherwise the continue is retried after 15, 30 and 60 minutes before giving up. Waiting rows show a check time separately from planned continues. Reservations and their sanitized context survive restarts, but need a lifecycle event or the Auto Resume screen to supply the API before checks run. Context overflow and API billing failures are excluded. Subagent continuation depends on the parent's available provider tools.
